## 1. Executive Summary & AI SDLC Workflow Framework

The **JARVIS Process Result Traceability Recording** module is a core capability within the Valeo MOM platform. It provides high-speed, zero-data-loss recording of manufacturing process results from PLCs, industrial computers, and third-party systems at line level (Edge PC) while synchronizing with the central plant database (Site Server).

## 2. Comprehensive Business Use Cases (VIB Compliance)

### 📂 BUC-0: Manufacturing Process Basic Modeling (4-Tier Hierarchy & Dual DB Sync)
* **4-Tier Hierarchy Model**:
  1. **Process Flow**: Product Reference (`MATERIAL-1`), Flow Code (`FLOW1`), Description.
  2. **Process Steps**: Ordered steps (`[11001] Housing Screwing`, `[11002] Body Sub Assembly 1`, etc.).
  3. **Process Operations**: Specific operations per step (`[123021] Screw 1`, `[123022] Screw 2`, `[123023] Screw 3`, `[123024] Screw 4`).
  4. **Process Result Definitions**: Parameters collected per operation:
     - `Result Code & Name` (e.g. `50032 Angle`, `50033 Torque`)
     - `Type`: Numeric (1), Text (2), File Ref (3)
     - `Specifications`: Nominal (e.g. 90 DD / 5 NU), LSL (80), USL (100)
     - `UOM`: (DD, NU, Text)
     - `Mandatory`: Boolean flag (`IsMandatory`)
* **Dual Console UI & Bidirectional Synchronization**:
  - **Site Admin Console UI**: Central process modeling and station-step mapping (`ST060.1 ➔ 11001`).
  - **Edge PC Local Console UI**: Direct view and line editing on Edge PCs. Edits mark status as `EDGE_MODIFIED` and synchronize back to the Site Server.
  - **Automatic Background Synchronization Engine**: Continuous, non-blocking background synchronization (`IHostedService` background worker loop running every 30s) automatically reconciling `jarvis_site_db` and `jarvis_edge_db` without manual user triggers, guaranteeing seamless offline resilience and zero configuration drift.

---

### 📂 BUC-1: Standard Process Results Storage Engine & Handshaking Protocol
* **Context Payload Binding**:
  - **Product Context**: `product_id` (`MATERIAL-1`), `product_serial_no` (UUID / barcode).
  - **Process Context**: `station_id` (`ST060.1`), `process_step_id` (`11001`), `station_mode` (`0=Serial`, `1=Prototype`, `3=Retest`, `4=Rework`, `5=MasterSample`), `process_step_result` (`1=PASS`, `2=NOK`, `3=SCRAP`), `wpc_no`, `machine_time`, `cycle_time`.
  - **Time Context**: Device timestamp (`TIMESTAMPTZ`) & Server system time.
  - **Process Results Array**: Operation IDs, Result IDs, numeric values, text strings, and file references.
* **PLC Handshake Protocol**:
  - Optional synchronous handshaking protocol: PLC sends trigger `1` ➔ MOM processes & validates ➔ Returns `ACK=1 / Status 200 OK` ➔ PLC releases workpiece carrier (<50ms SLA).
* **Zero Data Loss Degraded Mode Engine**:
  - Payloads with missing or unregistered station/serial context are NEVER dropped. Persisted as `DEGRADED_MISSING_CONTEXT` with raw JSON snapshot saved to `recording_audit_logs.raw_payload`.

---

### 📂 BUC-2: Low-Latency REST Ingestion API (< 50ms SLA)
* Endpoint: `POST /api/v1/traceability/process-results`
* Dual JSON Payload Support:
  1. **Nested VIB Benchmark Format** (`product_context`, `process_context`, `time_context`, `process_results`)
  2. **Flat API DTO Format** (`ProductSerialNo`, `StationId`, `ProcessStepId`, `ProcessResults`)
* Non-Blocking Architecture: Asynchronous dispatch to background `Channel<T>` for audit logging to guarantee `<50ms` synchronous HTTP response times.

## 3. Target AI-Enabled Delivery Workflow & Delivery Console Governance

The application incorporates the **Target AI-Enabled Delivery Workflow Orchestration Console** to visualize, stream, and govern the 6-phase delivery lifecycle:

* **Interactive 6-Phase Pipeline Stepper**:
  - Visualizes all 6 AI SDLC delivery stages (`Phase 01 Requirements`, `Phase 02 Design`, `Phase 03 Code`, `Phase 04 QA/SLA`, `Phase 05 Context`, `Phase 06 Release`).
  - Real-time Stage Gate Statuses: `APPROVED`, `IN_REVIEW`, `PENDING` (Locked).
* **Live Server Disk Artifact Streaming**:
  - Dynamically fetches raw markdown reports (`01_requirements_analyst_report.md` through `05_qa_reviewer_report.md`, `requirements.md`, `architecture.md`, `epics.md`, `AI_ENGINEERING_LOG.md`) from disk via backend REST API (`GET /api/v1/ai-sdlc/artifacts/{filename}`).
* **AI Token Utilization & Economics Dashboard**:
  - Displays live Input/Prompt Tokens, Output Tokens, Total Tokens, Prompt Caching Hit Rate (%), Latency (sec), and Cost Estimation ($ USD) per agent execution.
* **Persistent Human-in-the-Loop Gate Approval**:
  - Interactive approval button (`POST /api/v1/ai-sdlc/gates/{phaseNumber}/approve`) that appends server timestamps to `AI_ENGINEERING_LOG.md` on disk, unlocks Phase $(N+1)$, and updates backend state.
  - Reset gate endpoint (`POST /api/v1/ai-sdlc/reset-gates`) for live presentation re-testing.
